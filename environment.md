# Среда измерений

Аппаратная и программная среда, в которой выполнены измерения первого этапа трека [«Смена экземпляра сетевой функции»](research-track-instance-replacement.md). Сведения собраны 2026-10-06 во время прогона калибровки `results/2026-10-06T21-13-39_sweep-x`: с хоста (Windows, PowerShell/CIM), из Docker и изнутри работающих контейнеров стенда.

Каждый прогон дополнительно сохраняет краткую сводку среды в `results/<прогон>/environment.json`: версии Python, Windows, Docker и ядра, число CPU и объём памяти виртуальной машины, версию Compose и Envoy. Если среда меняется (обновление Windows, Docker Desktop, образов), этот документ нужно обновить, а в отчёте указать, какие прогоны в какой среде выполнены.

## 5. Конфигурация стенда

**Контейнеры:** `holder`, `envoy-a`/`envoy-b` (по очереди), `backend-1..3`, `loadgen`. Ограничений CPU и памяти у контейнеров нет: все делят 12 процессоров и 15,2 ГиБ виртуальной машины.

**Envoy** (`stand/envoy/envoy-a.yaml`, `envoy-b.yaml`; флаги — `stand/docker-compose.yml`):

| Параметр | Значение |
|---|---|
| Рабочие потоки (`concurrency`) | 12 — по числу процессоров ВМ (значение по умолчанию) |
| Запуск | `--disable-hot-restart`; `--drain-strategy immediate`; `--drain-time-s` = T |
| Уровень журнала | warn |
| Приём подключений | порт 8080, `enable_reuse_port: true`; оба экземпляра в сетевом пространстве `holder` |
| Протокол со стороны клиентов | HTTP/1.1 и HTTP/2 без TLS (h2c), `max_concurrent_streams` 100 000 |
| Тайм-ауты | `stream_idle_timeout`, `request_timeout`, тайм-аут маршрута и простоя — выключены (0) |
| Протокол к узлам сервиса | HTTP/1.1 (по умолчанию Envoy) |
| Балансировка | round-robin по трём узлам, `connect_timeout` 2 с |
| Пределы (circuit breakers) | подключения, ожидающие и одновременные запросы — 1 000 000; повторы — 0 |
| `parent_shutdown_time` | 900 с (по умолчанию; при `--disable-hot-restart` не используется) |
| Тайм-аут остановки контейнера Docker | 1 с (`stop_grace_period`); остановку выполняет оркестратор через `/quitquitquit` |

**Узлы сервиса:** лимит параллельности 100 000 на узел; при уходе клиента работа прекращается (`abort`); режим ответа задаёт сценарий (одним куском или потоком, раздел 6 трека). Тайм-аут остановки контейнера — 10 с.

**Генератор нагрузки:** HTTP/2 без TLS, одно соединение на клиента, открытая модель нагрузки (пуассоновский поток); тайм-аут остановки контейнера — 120 с.

**Часы:** все отметки времени в журналах — `CLOCK_MONOTONIC` ядра виртуальной машины. Системное время ВМ Docker Desktop скачет (часто примерно на 0,1 с, изредка до 3,5 с), поэтому для измерений оно не используется. Погрешность привязки часов контейнеров к хосту, измеряемая перед каждой точкой, — ±0,5–0,7 мс.

## 6. Условия измерений и их особенности

- Измерения выполнены на рабочем персональном компьютере. Во время прогонов могли работать другие программы (IDE, браузер, фоновые службы Windows). Ресурсы процессора и памяти с ними не изолированы.
- Windows и Docker Desktop добавляют слой виртуализации (WSL 2) между стендом и железом. Планировщик Windows, частота процессора (режим «Наилучшая производительность», boost) и фоновые процессы хоста влияют на виртуальную машину.
- Клиенты, Envoy и узлы сервиса работают в одной виртуальной машине: сетевой обмен идёт через виртуальный мост, без реальной сети.
- Итоговые измерения планируется повторить на Ubuntu с Docker Engine без виртуальной машины (раздел 9 трека). Для них нужен такой же документ.
